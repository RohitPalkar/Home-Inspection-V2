# Migration Report

## Overview

Migrated the Home Inspection Self-Survey application from **Lovable + TanStack Start + Nitro + Cloudflare** to a standard **React 19 + Vite + TypeScript + React Router** client-side rendered (SPA) application.

The original project was tightly coupled to Lovable's proprietary build tooling, TanStack's full-stack framework, and Cloudflare's serverless infrastructure — all of which were unnecessary for this purely client-side survey application.

---

## Architecture Changes

### 1. Framework

| Before                                     | After                                 |
| ------------------------------------------ | ------------------------------------- |
| Lovable (proprietary)                      | —                                     |
| TanStack Start (full-stack meta-framework) | React 19 (standalone)                 |
| TanStack Router (file-based routing)       | React Router v7 (declarative routing) |
| Nitro (server engine)                      | — (client-only)                       |
| Cloudflare Pages (deployment target)       | Any static host                       |

### 2. Build System

| Before                                                            | After                               |
| ----------------------------------------------------------------- | ----------------------------------- |
| `@lovable.dev/vite-tanstack-config` (opaque preset)               | Standard Vite with explicit plugins |
| Vite + SSR + Nitro build pipeline                                 | Single Vite client build            |
| `.output/`, `.tanstack/`, `.wrangler/`, `.vinxi/` build artifacts | Clean `dist/` output                |
| Cloudflare module worker target                                   | Static SPA output                   |

### 3. Routing

**Before (TanStack Router):**

```
src/routes/__root.tsx    — Shell layout with QueryClientProvider
src/routes/index.tsx     — Single route rendering SurveyApp
src/router.tsx           — createRouter with routeTree
src/routeTree.gen.ts     — Auto-generated by TanStack plugin
```

**After (React Router v7):**

```
src/main.tsx             — BrowserRouter wrapper
src/App.tsx              — Route definitions (/, *)
src/pages/SurveyPage.tsx — Survey route with ErrorBoundary
src/pages/NotFound.tsx   — 404 catch-all
```

### 4. Entry Points

**Before:**

- `src/start.ts` — TanStack Start instance with error middleware
- `src/server.ts` — Nitro SSR server entry with Cloudflare fetch handler
- TanStack Start handled `index.html` generation server-side

**After:**

- `index.html` — Standard Vite SPA entry with `<div id="root">`
- `src/main.tsx` — `createRoot` + `BrowserRouter` + `StrictMode`
- No server-side code whatsoever

### 5. Error Handling

**Before:**

- Lovable-specific `reportLovableError()` calling `window.__lovableEvents.captureException()`
- SSR error page rendered via `renderErrorPage()` in `src/lib/error-page.ts`
- Custom error capture in `src/lib/error-capture.ts` for h3/Nitro
- TanStack Router's built-in error boundary

**After:**

- Standard React ErrorBoundary component with `console.error` fallback
- 404 page via React Router catch-all route
- No Lovable, Nitro, or h3 error infrastructure

### 6. State Management

Unchanged — both versions use React `useState` for survey step progression and form data. No external state library is needed.

### 7. Styling

Unchanged — both use Tailwind CSS v4 with identical CSS custom properties, theme configuration, and `@tailwindcss/vite` plugin.

### 8. Accessibility

All WCAG 2.2 AA features preserved:

- Skip-to-content link
- ARIA roles and labels
- Keyboard navigation
- Focus management in modals
- Semantic HTML structure

### 9. Responsiveness

All mobile breakpoints (320px–1440px) preserved identically, including safe-area-inset support.

## Deployment

The new project produces a standard `dist/` folder that can be deployed to any static hosting provider:

- Vercel
- Netlify
- Cloudflare Pages (static mode, no worker needed)
- GitHub Pages
- AWS S3 + CloudFront
- Any web server
